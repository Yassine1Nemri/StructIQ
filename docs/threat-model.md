# Current threat model — Phase 4

Assets: user password hashes, access tokens, project metadata, memberships, and task details/assignment/deadlines. Only synthetic data is seeded. Private upload bytes and extracted pages are now assets; embeddings, retrieved context and Gemini credentials are also assets in Phase 4.

Trust boundaries: browser → loopback nginx → Spring API → private PostgreSQL. FastAPI is private and provides HMAC-authenticated extraction in addition to health. Spring, not UI controls or JWT role claims, determines project access. Runtime image users are unprivileged. The frontend receives public DTOs only.

| Threat | Implemented control and proof |
| --- | --- |
| Project ID guessing / cross-project reads | Scoped repository queries and service membership checks; HTTP tests deny other-project detail/member reads; live smoke proves two-user isolation |
| Project mutation / member ID mismatch | Manager checks, project-row lock, and membership writes filtered by both project and user IDs; automated mutation isolation tests |
| Self-promotion / false role claims | Role permissions come from the database, not caller input or JWT role; HTTP tests deny member escalation even with an ADMIN claim |
| Stale privileges | Current user and membership loaded on each operation; tests revoke membership and demote admin while retaining the same token |
| Invalid / expired JWT | HS256-only decoder, minimum signing-secret length, issuer, audience, expiry and UUID subject validation; negative token tests |
| Password guessing / account enumeration | BCrypt cost 12, generic credential errors, dummy hash for unknown emails, bounded per-address login limiter; unit and HTTP rate-limit tests |
| SQL injection / leaking password hashes | Parameterized queries, escaped literal search wildcards, explicit public DTOs; malformed-input and response tests |
| CSRF / token persistence | Stateless Authorization bearer API with no cookie/session authentication; browser omits cookies and retains token in memory; client tests cover bearer clearing |
| Accidental service / secret exposure | AI/DB have no host ports; web/API bind loopback; ignored private `.env` and generated credentials; Compose boundary checks |
| Operational detail leakage | Sanitized error bodies with server-generated correlation IDs; detailed actuator endpoints denied; health exposes status/group names only |

Residual risks: localhost HTTP is for development, not deployment. Production needs HTTPS, a dedicated migration/runtime database privilege policy, a trusted reverse proxy, distributed rate limiting, and secret rotation. nginx-proxied local logins share one remote address and therefore one rate limit. Signing-key rotation invalidates existing tokens, but logout otherwise clears only the browser token; a stolen token is valid until expiry unless the user is deleted or loses resource permission. XSS can use an in-memory token while the page is active; CSP, React escaping, and no raw-HTML rendering reduce exposure but are not complete XSS proof.

The built-in seed is opt-in and local-only; generated credentials must not be used in real deployments. Managers can grant other registered users project access intentionally. Project member emails are visible to other members of that project. Last-manager changes are serialized on the project row. Validation rejects malformed requests without echoing bodies. Browser E2E, vulnerability scanning, and live-model prompt behavior remains unverified; mocked-provider RAG permission tests are implemented. H2 integration tests are supplemented by PostgreSQL live smoke rather than claimed as PostgreSQL/Testcontainers integration tests.


## Phase 2 controls and proof

Task reads and writes are scoped by both project ID and task ID; HTTP tests reject guessed cross-project IDs even when the caller belongs to both projects. ADMIN/manager can manage tasks; MEMBER may update only status of their own assigned task. Presence-aware PATCH rejects extra fields for members even when null. VIEWER cannot update assigned tasks. Tests cover these cases and invalid enums, dates, title limits, and unknown PATCH fields.

Assignee membership is checked under the project row lock and enforced again by a composite database foreign key from `(project_id, assignee_id)` to membership. All normal task and membership mutations serialize on that project lock. Removing membership first unassigns that project's tasks within the same transaction, then removes membership; the removed user immediately loses task/My Tasks access. Project deletion explicitly clears tasks before deleting project/memberships, avoiding constraint-order conflicts. Tests exercise foreign-assignee rejection, a direct database bypass attempt, revocation/unassignment, and deletion cleanup.

Dashboard and My Tasks enforce current membership in SQL before returning rows, counts or deadline lists. Dashboard uses a repeatable-read transaction so grouped metrics and lists share a snapshot. Tests place tasks in two projects and prove only accessible counts/rows appear, including progress changes after completion. Live PostgreSQL smoke repeats task policy and metric-delta checks through nginx. Frontend rendering tests check member/viewer/manager controls and data-driven metrics, but do not substitute for backend authorization or browser E2E testing.

Remaining Phase 2 limitations: all known statuses may transition freely; concurrent edits are serialized but use last-writer-wins rather than version conflicts. Dashboard previews are bounded to eight projects and ten tasks per deadline list. Large-scale query tuning has not been measured. Seed deadlines are relative to first creation and preserved on reseed. Browser access is unavailable; visual QA and click-based E2E are unrun. Document controls are implemented below; RAG controls are implemented below.


## Phase 3 controls and proof

Uploads/downloads/deletion/retry authorize current project membership on Spring. All document lookups use both project ID and document ID. VIEWER cannot mutate documents; MEMBER may delete only their own uploads; ADMIN/MANAGER can delete any. Tests and live smoke cover guessed IDs, mismatched IDs despite access to both projects, revocation, viewer permissions, and uploader deletion. Public metadata DTOs omit raw text, storage keys and checksums. Downloads are attachments with no-store and nosniff, and nginx has no private volume mount.

Uploads have strict byte/type/extension checks, generated UUID paths, safe display names and POSIX permissions. Tests reject binary/executable signatures, markup disguised as text, invalid UTF-8, mismatched types, empty files and oversize bodies; duplicate/path-traversal filenames cannot select storage paths. pypdf additionally validates structure and preserves page numbers. Parser subprocess CPU/memory/time and page/text limits reduce resource exhaustion; two parser slots bound concurrency. These are not antivirus controls, and active PDF content is not comprehensively inspected or stripped. Users should treat downloaded documents as untrusted files.

Internal calls use a shared independent secret and HMAC-SHA256 over method/path/timestamp/nonce/body digest. Tests reject missing/tampered/expired/future/replayed requests and arbitrary extra storage keys; parsing derives paths from authenticated UUID context and rejects symlinks. AI mounts the private volume read-only and receives no browser-published port. A test passes hostile instructions as text and verifies they remain data; no commands, URLs, tools or model calls are dispatched by document text. This is extraction proof, not full RAG prompt-injection proof.

Metadata/page deletion and a durable storage cleanup outbox commit atomically. After-commit cleanup and scheduled retries remove bytes; a simulated storage outage proves the cleanup record survives for retry. Project deletion clears documents/pages and queues files. A removed metadata record cannot be downloaded even while cleanup is pending. Interrupted processing becomes FAILED and supports explicit retry. Parsed pages are private and constrained by a composite project/document foreign key; vector chunks now cascade on document/project deletion in Phase 4.

Residual risks: a hard process crash after file creation but before metadata commit can leave inaccessible orphan bytes; no automatic orphan reconciliation exists. Preserve the database and volume together for backups. The shared secret and read-only parser mount are privileged trust boundaries; compromise of the parser process can expose mounted document data. Replay cache, cleanup throughput and parser capacity target a single-instance demo, not a multi-replica production workload. Browser rendering/E2E and vulnerability scans remain unrun. No provider key or real customer document is required for this phase.


## Phase 4 controls and proof

Spring authorizes each AI status/ask/index path and holds a project lock during index/ask to prevent normal membership/source mutations from racing provider context use. VIEWER can ask but cannot index. HMAC binds operation, timestamp, nonce, project and complete body; an extract signature cannot authorize ask/index. Database retrieval takes the trusted signed project ID and applies chunk/document project, READY, embedding model/dimension restrictions in SQL before exact top-k. A real pgvector proof constructs closer foreign chunks and still returns the authorized project at top-1. READY/model mismatches are excluded; composite foreign keys and vector(768) reject mismatched project/document IDs and dimensions.

Embedding output is dimension-checked, finite/nonzero and normalized; model identity accompanies each chunk. Chunk replacement plus READY commits atomically. A missing provider key/model returns AI_NOT_CONFIGURED before provider calls. New uploads remain usable when indexing fails. Deleting a document/project cascades chunks, so stale source IDs cannot be cited or retrieved. Tests cover deletion and independently check citation references against currently READY scoped data on Spring.

Provider generation receives only a bounded question and up to six allowed excerpts, marked untrusted, with no tools. Structured output supplies integer source indices; out-of-range or malformed sources are rejected, and absent sources produce a fixed insufficient-information answer. Python builds citations from retrieved rows; Spring rejects mismatched IDs, filenames, page numbers, fabricated excerpts, stale READY state and unsupported uncited answers. The UI renders answer text as escaped text, never raw HTML, and fetches citations using the in-memory bearer token. Answers include a human-verification note. Prompt-injection tests prove that document/prompt text cannot broaden SQL scope or invoke tools; they do not prove a live model will never make a factual or instruction-following error.

AI joins a dedicated NAT egress bridge to reach fixed Google HTTPS endpoints; its service port remains unpublished. PostgreSQL stays on the isolated network and nginx has no private volume or Gemini key. Keys use request headers rather than URL query strings and no provider payload/response diagnostics are logged. Two internal service slots, bounded context/output, per-request timeouts and an indexing deadline constrain work. Indexing/questions are synchronous and may delay other writes in that project.

Residual risks: the default local AI DB account shares broad demo credentials; production needs a restricted database role and scoped grants. The in-memory replay cache and service capacity are single-instance controls. No per-user AI quota or retry queue is implemented. Real Gemini account/model availability, generation quality and relevance threshold tuning were not tested; deterministic proof injects a provider fixture only into a separate test image/stack. That fixture is absent from the normal runtime image. Browser clicks/visual QA, dependency/image scans and Jenkins execution remain unrun. Previously documented storage-crash/orphan, OCR/antivirus, TLS and login/proxy limitations still apply.


## Local Ollama provider amendment

`AI_PROVIDER=ollama` sends only signed-service-authorized questions/retrieved project excerpts or indexing text to the configured host Ollama endpoint. Browser callers cannot select the endpoint, model, provider, or SQL scope. No cloud API key is required. The Ollama API itself does not enforce StructIQ membership; limit its listener/firewall access to trusted local clients/container networks. Compose adds host-gateway resolution only, without host networking or published AI/DB ports. Never proxy Ollama directly to browsers. No host firewall/listener changes are performed by the app.

Provider-qualified embedding model IDs and strict normalized vector(768) validation prevent mixing Gemini and Ollama vectors. Reindex on provider/model changes. Structured generation has no tools and treats retrieved text as untrusted; the existing SQL scope, READY-only selection, source-number validation and Spring citation validation remain in force. Local calls have bounded longer timeouts (60 seconds/provider, 150 seconds/internal, 180 seconds/nginx); project locks may be held longer. The 0.35 relevance cutoff has only a synthetic local smoke check, not a representative retrieval benchmark.
